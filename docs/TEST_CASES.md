# P0 实机验证步骤与记录表

目标探针 `0.1.1-probe`，绑定标识 `JX3CP_P0_PING`，显示名称 `JX3CP Debug Ping`。

## 实机步骤

1. 从正常启动器启动旗舰版，记录画面上的完整版本、分支及时间；对照本机配置版本 `1-6-0-10024`。需要登录时由用户操作。
2. 在正常插件管理器检查 `JX3CP Prototype P0`。本次目录为 `bin/zhcn_hd/interface/JX3CP_P0`，默认禁用。记录未出现、拒绝认证、可启用三者中的实际结果。未出现时先核对目录层级，不推断 Lua 已报错；拒绝认证时停止加载验证。
3. 如可正常启用，使用客户端正常重载/重新进入流程；在允许的调试输出中寻找 `[JX3CP-P0] Lua entry executed; version=0.1.1-probe`。日志渠道缺失时，内存缓冲只作后续诊断，不能算“可见日志通过”。
4. 检查输出中的 `Hotkey.AddBinding`。`false` 表示入口可运行但该能力不可用；`call_ok_unverified` 表示调用未失败，需要继续看快捷键设置。
5. 在快捷键设置查找 `JX3CP Debug Ping`，记录分组及显示名称。若能找到，先保存原绑定并选一个无冲突测试键。不要使用战斗、聊天、移动或界面常用键。
6. 非战斗安全场景中，短按并释放一次。必须恰有 `DOWN (count=1)`、`UP (count=1)`。再重复两次，累计各为 3；保存日志/截图及按键名称。
7. 验证长按是否重复 DOWN、焦点切换是否丢 UP，并如实记录。这些行为尚未确认，不能由离线模拟结果推断。
8. 关闭插件并走正常重载流程，恢复测试键原绑定，确认键鼠正常。卸载只能在确认客户端关闭后处理本次独立插件目录。
